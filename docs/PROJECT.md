# 프로젝트 요구사항과 설계

## 목적과 환경
현대자동차 Pleos 공모전용 차량 오디오 학습 앱. 실제 Pleos 에뮬레이터에서 핵심 기능이 작동하는 프로토타입을 목표로 한다.
- Windows / Android Studio / Kotlin / Jetpack Compose + Material 3
- 프로젝트: PleosAudioGuide / 패키지: com.example.pleosaudioguide / 단일 :app
- minSdk 28, compileSdk·targetSdk 37
- 테스트 대상: Pleos Connect v2.1.0

## 개발용 화면 미리보기
- app/src/debug/java/com/example/pleosaudioguide/ui/ScreenGallery.kt의 ScreenGalleryPreview에서 19가지 샘플 상태 제공. Android Studio debug 빌드 변형에서 파일을 열고 Split/Design → Preview 새로고침. Interactive 모드의 상단 선택 메뉴로 이동·샘플 퀴즈/보관함 상세 조작 가능.
- 기존 화면 Composable을 사용하며 샘플 데이터 배너를 항상 표시한다. ViewModel·Room·차량 SDK·실제 오디오·LLM 호출 없이 표시하고 release에는 포함되지 않는다. 공통 실제 앱 프레임/미니 플레이어는 별도 실기 검증 대상이며 이 모음은 화면 본문 위주다.

## 초기 개발 범위
- 내비: 현재 목적지 이름·위치, 남은 예상 주행시간 조회, 목적지 변경·도착 이벤트 처리.
- 목적지 추천: 준비된 콘텐츠와 장소·지역 매칭 규칙, 남은 시간에 맞는 길이 우선.
- 일반 콘텐츠: 관광·역사 / 일반 상식 / 어학 학습 / 기타 교양 카테고리와 목록에서 직접 선택.
- 플레이어: 수동 선택, 재생·일시정지, 이전·다음, 진행률, 제목·시간, 연속 재생, 플레이리스트 관리.
- 퀴즈: 이번 운행에서 청취했고 누적 80% 이상 완료된 대본으로 LLM이 최대 10문제(보기 3개)를 먼저 준비한 뒤 확보한 수에 따라 가볍게·충분히·깊게 분량을 선택. 정답 확인·해설·대본 근거·결과 및 Room 풀이 복원. 안전한 주차에서만 진행.

## 퀴즈 검사 완화 (2026-11-14)
- 앱/서버 공통으로 자연스러운 정답 풀어쓰기 허용, 근거 최소 8→2자, 공백·문장부호 차이 허용. 출처/대본 내 근거·중복·보기 3개·정답 인덱스 검사는 유지한다. 의미적 정답성은 문자열 검사로 보장하지 않는다.
- 짧은 대본은 장소·인물·특징·핵심 내용의 쉬운 1~3문제를 우선 요청한다. 모델/키는 변경하지 않으며 1~10개 사전 준비·분량 선택·기존 퀴즈 캐시는 유지한다. 서버 재시작과 앱 재설치가 모두 필요하다.

## 퀴즈 사전 준비·분량 선택
- 종료 안내의 '퀴즈로 음악 완성하기' → 준비 중/오류·재시도 → 검증된 문제 수를 확보한 뒤 분량 선택 → 풀이. 진입 시 최대 10문제를 요청하고 1~10개를 허용한다. 선택 이후에는 LLM을 다시 호출하지 않는다.
- 가볍게: 최대 2개, 충분히: 최대 5개(3개 이상 확보 시), 깊게: 확보한 전체 최대 10개(6개 이상 확보 시). 1~2개면 가볍게만 활성화하며 각 선택에 실제 문제 수·30초/문제 예상 시간을 표시한다.
- 서버는 근거 없는 문제/중복 후보를 제외하고 검증된 문제가 1개 이상이면 제공한다. 0개·거부·불완전·통신 오류는 재시도 안내. 생성한 전체 문제와 분량별 풀이를 기존 Room 운행/실제 문제 수 키로 보관한다. 과거 저장 퀴즈도 최대 개수를 준비 목록으로 재사용한다.
- 요청 count는 최대 개수(1~10), 응답 count는 실제 반환 개수. 앱·서버를 함께 업데이트하고 실행 중 서버를 재시작해야 한다.

## 누적 청취 완료 정책 (2026-11-13 갱신)
- 이번 운행에서 실제로 재생한 콘텐츠만 후보로 삼고, 동일 ID·대본·재생 방식의 출발 전/이전 운행 기록을 합친다. 겹친 구간은 중복 계산하지 않으며 실제 길이의 80% 이상이면 완료로 인정한다. seek한 위치 자체는 청취량이 아니다.
- 운행 종료 시 누적 완료 판단용 기록을 history_meta의 trip-completion:v2:운행ID에 고정한다. 원본 운행별 snapshot은 그대로 유지한다. 기존 운행은 종료 시점 이전으로 확인 가능한 기록으로 한 번 계산하며, 이후 청취로 과거 결과를 바꾸지 않는다. DB 스키마 변경 없음.
- 완료 콘텐츠 중 대본이 있는 항목으로 퀴즈를 만든다. 문장 타임코드가 없어 전체 대본을 사용하며 미청취 20%에서 출제될 수 있음을 화면에서 안내한다. TTS는 구간 측정이 없어 정상 완료 이벤트 기준을 유지한다.
- 아래 초기 100%/해당 운행만 기준은 이 정책으로 대체한다. 기존에 생성·저장한 퀴즈는 다시 생성하지 않는다.

## 탐색 기본 화면 (serach)
- 이미지 기준 POT-QUEST 로고/검색 진입/카테고리 6개/지금 주목할 프로그램 구성. 카테고리 카드는 모두 흰색, 선택 테두리로 구분. 공통 하단 탭·미니 플레이어는 GuideApp 소유 유지.
- 검색은 현재 Odii 조회 결과+기본 카탈로그의 제목·분류·장소 태그 부분 일치만 제공. 빈 검색은 전체, 결과 없음은 명시. 카테고리는 기존 메타데이터 키워드로 임시 분류하며 서버 검색·고급 정렬/추천은 제외한다. 콘텐츠 선택만 기존 onPlay(필터 결과, 인덱스) 호출.
- 오늘 최다 재생: 구현 가능하지만 현재 DB는 합쳐진 청취 구간/최근 시각만 저장하므로 정확한 일일 재생 횟수를 복원할 수 없다. 기기 내 순위는 별도 재생 시작 이벤트(콘텐츠 ID/시각)·중복 기준/날짜 경계가 필요하고 전체 사용자 순위는 서버 집계가 필요하다. 현재 순위 데이터가 없어 '오늘의 인기 오디오 집계 준비 중' 표시. 가짜 인기 목록/횟수는 만들지 않는다.
- 탐색/검색은 기존 P·정차·UX 해제 조건에서만 노출한다. 주행 중 기본 오디오 화면 정책 유지.

## 운행 종료 안내 UI (issue_02)
- 제목은 가운데 정렬, 나의 항아리 캡션·서버 전송 설명 제거. 출제 가능 시 '청취한 n개 에피소드에서 학습재료를 준비했어요'와 '퀴즈 물약 완성하기' 표시. 출제 0개는 기존 홈 복귀·원인 안내 유지.
- 항아리 영역은 화면 폭/높이에 맞춰 최대400dp. 큰 화면에서 종료 제목·본문·버튼 글자는 폭 기준 최대1.6배 확대(본문20sp/행간28sp 기준). 섹션 간격은 높이5%, 24~64dp로 제한해 완료0개에서도 남는 높이를 빈 공간으로 늘리지 않는다. 작은 창은 스크롤 지원. 공통 헤더 로고는 일반76dp 기준 최대1.6배, 좁은창64/주행 축소44dp이며 일반 헤더 이름·상태 글자도 폭에 맞춰 확대.

## 운행 종료 닫기와 출제 없음 상태
- 퀴즈 진입 전 운행 종료 화면의 나의 항아리는 drawable/pot.png를 사용한다. 기존 200dp 표시 영역 안에서 원본 비율을 유지한다.
- 종료/퀴즈의 나중에 하기·홈으로는 종료 안내의 표시 해제와 함께 홈 탭/첫 화면으로 돌아간다. 이전에 열려 있던 재생 화면·콘텐츠 목록 상태는 닫되 오디오를 자동 재개하지 않는다.
- 출제 가능한 대본 0개면 퀴즈 버튼·서버 전송 설명을 숨기고 홈으로만 제공한다. 완료 콘텐츠 0개와 완료했으나 대본 없음 상태는 설명을 구분한다.
- 닫기는 포션 생성 조건이 아니다. 최초 누적 80% 도달 시 저장하고, 완료 항목이 없으면 새 포션을 만들지 않는다. 보관함은 현재 조회 전용이며, MY POT에서 최신 운행의 동일 분량 저장 퀴즈를 재개하는 경로와 구분한다.

## 보관함 선반·완료 귀속 (storage)
- 4칸×3줄, 페이지당 12개 학습 묶음. 데이터 없는 칸은 빈 선반, 13번째부터 다음 페이지. 같은 운행 또는 같은 날짜의 자유 청취 완료 콘텐츠를 한 포션에 묶는다. 미완료 청취는 구간/이어듣기에만 저장하고 포션을 만들지 않는다.
- 동일 ID·대본·방식의 실제 누적 청취가 처음 80%에 도달한 시각과 당시 운행 ID(없으면 자유 청취 날짜)를 library_completion에 고정한다. 재청취로 중복 생성/날짜 이동하지 않는다. 이후 운행 퀴즈도 해당 운행에 처음 귀속된 완료 콘텐츠만 대상으로 삼는다. TTS는 정상 완료 이벤트 기준.
- Room v3 library_completion 추가, v2→v3 자동 이전. 기존 청취·퀴즈는 유지하고 과거 완료 기록은 마지막 확인 자료로 이관하되 최초 완료 시각을 알 수 없어 '이전 기록·완료 시점 미확인' 표시. 기존 운행별 raw 기록/이어듣기/퀴즈 캐시는 삭제하지 않는다.
- 포션을 누르면 귀속 오디오 목록과 저장된 퀴즈·선택 답·확인한 정답/해설을 조회한다. 관련 묶음의 퀴즈 하나를 완료하면 컬러, 미완료/미생성이면 회색. 전체 문제 생성 캐시와 실제 풀이를 중복 목록으로 표시하지 않는다. 이번 단계는 상세 조회까지이며 보관함에서 과거/자유 청취의 새 퀴즈 생성·이어풀기·오디오 재청취 진입은 후속 범위다.
- 포션 이미지는 app/src/main/res/drawable/potion_이름.png(WebP/XML도 가능)에 둔다. 등록된 potion_* 중 새 묶음 생성 시 무작위 선택해 리소스 이름을 DB에 저장한다. 2026-11-14 potion_01~potion_19 PNG 19종 등록 확인. 기존에 pot_placeholder로 저장된 포션은 그대로 유지하고 신규 묶음부터 등록 이미지 중 선택한다. 같은 이름을 유지해 원본을 교체하면 기존 포션에도 반영된다. 미완료 회색은 앱이 처리하므로 별도 회색 파일 불필요. 저장 후 이미지 추가만으로 기존 선택을 다시 추첨하지 않는다.
- 검색/홈과 동일한 공통 하단 탭·미니 플레이어 유지, 기존 주차/UX 제한 내에서만 접근.

## 주요 설계 결정
- 일반 콘텐츠는 내비·추천과 독립적으로 항상 제공한다. 목적지가 있어도 자유롭게 선택할 수 있다.
- 목적지 추천과 일반 목록은 UI에서 구분하고 공통 플레이어·재생 큐를 사용한다.
- 목적지 변경으로 사용자의 재생 콘텐츠나 큐를 자동 교체하지 않는다.
- 직접 등록한 로컬 콘텐츠 데이터로 시작한다. 첫 시연은 음원 부재로 등록 원고를 Pleos TextToSpeech ON_DEVICE 모드로 재생한다(서버·AI 생성 없음). 추정 길이와 실제 재생시간을 구분한다. 녹음 음원은 AudioContent.audioUri에 연결하며 Media3로 재생한다.
- 추천은 관련성 우선, 남은 시간 내 재생 완료 가능 여부를 고려한다. 시간이 없으면 관련성만 사용하며, 관련 콘텐츠가 없으면 일반 콘텐츠를 안내한다.
- 단일 앱 구조를 유지한다. MainActivity는 화면, GuideViewModel은 상태·동작 조율, NavigationSource는 SDK→앱 목적지 변환, ContentCatalog/ContentRecommender는 데이터·규칙, PleosNarration/GuidePlaybackService는 음성·음원 재생을 담당한다. UI·추천 규칙 변경을 각 경계 안에서 처리한다.
- Media3 ExoPlayer + MediaSessionService는 등록 음원용으로 구성했다. 첫 시연의 Pleos TTS는 직접 재생 경로로, 중지·처음부터 재생을 제공한다. TTS의 정확한 진행률·일시정지·시스템 미디어 제어는 미지원이며 녹음 음원 단계에서 검증한다. 내비 화면 전환·백그라운드·오디오 포커스도 추가 검증한다.
- 콘텐츠 목록은 연한 배경·흰 카드·오디오 썸네일·오른쪽 ic_dragle_handle, 상단 logo 이미지와 정차 표시를 사용한다. 행 전체가 재생 진입이며 별도 듣기 버튼과 전역 순서 변경/위아래 편집 행은 제거했다. 순서 번호는 화면에 표시하지 않고 현재 항목의 재생 상태 문구·테두리만 유지한다. 순서별 베이지 명도도 제거한다.
- 핸들 드래그는 보이는 인접 항목으로 이동하며, 핸들 탭은 맨 위/위/아래/맨 아래 메뉴를 연다. 재생 전 항목은 화면별 임시 순서를 보존하여 다음 재생 요청에 전달한다. 큐에 있는 항목은 기존 onMoveItem으로 실제 큐만 이동하며 다른 그룹(큐/미등록) 사이로 드래그해 자동 추가하지 않는다. 화면 순서의 DB 영구 저장·드래그 자동 스크롤은 미구현이다.

## 홈과 화면 전환 (2026-11-10)
- 홈 순서: 목적지 기반 팟캐스트 → 오늘의 퀘스트 → 추천 에피소드. 이어서 듣기 카드는 제거하고 공통 하단 미니 플레이어로 통합한다.
- 추천 에피소드는 OdiiStore의 실행 중 확보한 실제 HTTPS 음원과 현재 조회 결과를 ID 중복 제거한 뒤 무작위 최대 5개 선택. 후보가 바뀌기 전 재구성에서는 선택/순서 유지. 홈과 일반 추천 목록이 같은 선택을 사용하며 예시 TTS는 이 영역에서 제외, 후보 없음은 안내한다. 기본 콘텐츠는 다른 일반 탐색/퀘스트 경로에서 유지한다. 전체 지역 카탈로그 조회/영구 캐시가 아니므로 확보한 음원이 한 지역뿐이면 해당 지역 안에서 무작위 선택한다.
- GuideApp이 고정 하단 메뉴(홈/탐색/보관함/MY POT)와 미니 플레이어를 소유한다. 탭별 스크롤과 선택 탭을 보존하고 공통 GuideViewModel을 유지한다.
- 미니 플레이어는 현재 세션 또는 저장된 이어듣기 콘텐츠가 있으면 표시한다. 저장 기록만 있을 때는 제목·썸네일·저장 위치/길이와 이어서 듣기(시연 TTS는 처음부터 듣기)를 제공하고 이전/다음은 비활성화한다. 썸네일은 모달 없이 전체 재생 화면으로 바로 이동한다. 현재 세션이 없으면 저장 콘텐츠·위치를 일시정지 상태로 준비하고, 세션이 있으면 큐·위치·재생/일시정지를 그대로 유지한다. 저장 기록만 있을 때의 이어서 듣기 버튼은 기존 재개 선택 모달 경로를 유지한다. 재생 중에는 기존 전체 화면 진입·재생/중지·이전/다음을 유지한다. 표시 자체로 자동 재생하지 않는다.
- 실제 음원은 Room history_meta의 playback:콘텐츠ID / playback:latest에 재개 위치·길이·콘텐츠 정보(음원/이미지 주소·대본 등)를 저장한다. 서비스에서 주기/이벤트/전환 직전 위치를 수집하고 앱 재실행 시 마지막 미완료 음원 정보를 복원한다. 기존 SharedPreferences 북마크는 호환용으로 유지한다. 청취 구간·운행별 퀴즈 판정과 재개 위치는 독립적이며 seek를 청취로 인정하지 않는다. TTS는 위치 이어듣기가 불가하므로 '처음부터 다시 듣기'로 표시한다.
- 안전한 주차 상태에서 목록/이어서 듣기/수동 이전·다음/캐러셀로 저장 위치가 있는 음원을 선택하면 '마지막 재생 위치 / 전체 길이'와 처음부터·이어듣기 모달을 표시한다. 선택 전에는 기존 재생을 유지하고 닫기는 전환을 취소한다. 캐러셀/수동 이전·다음은 재생·일시정지를 보존하며 목록 선택은 기존 정책대로 재생한다. 자동 다음 재생도 서비스에서 기존 위치 조회 후 일시정지하고 같은 모달을 표시한다. 선택 전 0초 위치로 기존 기록을 덮어쓰지 않으며, 모달 닫기는 저장 위치를 유지한 채 일시정지한다. 주행 중 자동 다음 재생도 유효한 차량 상태에서는 같은 주행용 모달을 표시한다. 상태 불명/오류·종료 안내 중에는 모달 없이 저장 위치에 일시정지하며 자동 재개하지 않는다. 일반 수동 선택 모달은 주차 해제·운행 종료 안내 진입 시 취소한다. 주행 중 사용자가 인접 항목을 스와이프한 경우에는 유효한 차량 상태에서만 처음부터/이어듣기 모달을 허용하고, 신호 유실·오류 또는 종료 안내 진입 시 취소한다. 자동 전환 선택창도 신호 유실/오류 시 닫고 저장 위치에서 일시정지한다. 완료/0초 위치·TTS에는 모달을 띄우지 않는다. 새 기능 도입 전 콘텐츠별 재개 위치는 소급 복구할 수 없고 기존 마지막 북마크만 호환한다.
- 홈의 목적지 추천/오늘의 퀘스트/추천 에피소드를 누르면 콘텐츠 선택 목록으로 이동한다. 홈의 전체 보기·목록 보기 버튼은 표시하지 않고 섹션 제목/카드/행 자체의 클릭 진입을 유지한다. 목록 상단의 목적지 추천·오늘의 퀘스트·일반 추천을 전환할 수 있다. 목록 진입·분류 변경으로 자동 재생하거나 기존 큐를 바꾸지 않고, 항목 선택 시 해당 목록과 인덱스를 공통 플레이어에 전달한다.

- MainActivity에 distractionOptimized=true를 선언하되, 검증된 P·속도 0·UX 해제 이외에는 DrivingPlayerScreen만 표시한다. 최초 신호 대기·권한 거절·연결 오류도 같은 제한 화면을 사용한다.

ViewModel에서 일반 임의 위치 seek/항목 선택/순서 변경은 계속 차단한다. 별도 주행 명령은 고정 30초 이동(범위 제한)과 현재 큐 인접 선택만 허용하고, 전환 직전 현재 위치를 저장하고 대상 콘텐츠의 Room 재개 위치를 조회한다. 저장 위치가 있으면 스와이프와 자동 다음 전환 모두 처음부터(0초)/이어듣기(저장 위치) 선택창을 표시한다. 자동 전환은 이미 다음 항목에 도착한 상태에서 일시정지하고 선택 후 재생하며, 닫으면 저장 위치에서 멈춘다. 수동 스와이프는 선택 전 기존 항목을 유지하고 닫기는 전환을 취소한다. 주행용 선택창은 불필요한 설명을 숨기고 제목 길이를 제한하며 버튼은 최소 높이 64dp/너비 112dp로 제공한다. 차량 데이터 불명·오류에서는 선택 요청/선택창을 허용하지 않는다. 미청취/실제 끝 위치는 0초부터 시작하며 기존 재생/일시정지는 유지한다. 조회 응답 적용 전 요청 번호·원래 항목·인접 순서·종료 안내를 재확인한다. 운행 종료 안내 중에는 두 명령도 차단한다. 타이틀은 플랫폼 최대 문자열 길이를 적용한다. - 속도 권한 요청은 UX 제한이 해제된 전경 상태에서만 표시하고, 주행/불명 상태에서는 권한 설정 UI도 띄우지 않는다.

- 2026-11-14 공개 Pleos 주행 안전·규제·Music/Audio 가이드와 Google 차량용 Dialog 문서에서 짧은 재생 선택 모달의 일괄 금지를 확인하지 못했다. 이를 기본 오디오 제어의 간단한 재생 선택으로 해석하며, 사용자 요청에 따라 수동 스와이프와 자동 전환에 적용한다. 핸들 미디어 키의 기본 재생 제어와 모달 버튼의 포커스 이동/확인 매핑은 별개이며, 현재 핸들로 모달을 선택하는 연동·실차 검증을 완료한 상태는 아니다. 일반 설정/검색/퀴즈의 주차 잠금은 유지하며 비공개 UX 규제 사양·실차 심사 승인과 구분한다. 근거: https://document.pleos.ai/docs/pleos-only/vehicle-app-planning-guide/driver-distraction-guideline , https://developers.google.com/cars/design/automotive-os/components/dialogs .

## 청취 기록과 운행 종료 (quiz, Room)
- 콘텐츠별 재개 위치는 기존 history_meta에 이름 공간으로 구분해 저장하므로 이번 기능은 DB 버전/마이그레이션을 변경하지 않는다. 전체 큐의 영구 복원·여러 운행의 청취 구간을 합친 퀴즈 완료 판정은 별도 범위다.
- Room 2.8.4 / KSP 2.3.5, 앱 내부 listening.db v3에 운행(trips), 운행별 청취(listening), 이관 상태(history_meta), 운행/문제 수별 문제·답안·채점 상태(quiz_attempts)를 저장한다. v1→v2 자동 마이그레이션으로 기존 기록을 보존한다. 청취 대본·구간은 기존 버전 JSON 코덱을 재사용한 payload 열로 보존한다. 음원 파일·인증키는 저장하지 않는다.
- ListeningHistoryStore의 단일 작업 큐로 DB·차량 이벤트를 직렬화한다. snapshot(tripId)으로 해당 운행만 조회한다. 같은 콘텐츠도 운행/대본/재생 방식이 다르면 분리한다. 기존 JSON은 트랜잭션으로 legacy-json에 1회 이관하고 삭제하지 않는다. 이관 실패는 오류로 남기고 새 Room 기록은 저장한다.
- 실제 주행(유효 차량 속도 절댓값 > 0.1m/s)을 관측하면 UUID 운행을 시작한다. P + 속도 절댓값 ≤ 0.01m/s + UX 제한 해제가 5초 유지되면 종료한다. 처음부터 주차/신호 대기/짧은 P/권한·신호 불명 상태는 종료로 판단하지 않는다. 이는 앱의 운행 세션 기준이며 시동 OFF 또는 운전자 의도를 확정하는 신호가 아니다.
- 운행 밖 청취는 outside-trip에 보관해 운행 퀴즈에 섞지 않는다. 프로세스 재시작 후 열린 운행은 이어서 추적하되 최신 차량 상태 확인 전에는 종료 UI를 표시하지 않는다. 프로세스가 죽어 있는 동안의 운행 경계는 복원할 수 없다.
- 종료 후 안전 상태에서 TripFinishedScreen을 자동 표시한다. 임시 벡터 항아리, 이번 운행 청취/대본 수, 나중에 하기 제공. 요청에 따라 제목 바로 아래 설명은 생략한다. 출제 가능한 대본이 있으면 퀴즈 준비 화면으로 이동한다. 실제 생성은 중계 서버·LLM 키 설정이 필요하며 보상 음악 생성은 범위 밖이다. 나중에 하기/뒤로는 해당 운행 표시를 영구 해제한다. 재주행/신호 불명 시 즉시 숨긴다. 운행 종료 안내 진입 시 Media3는 위치·큐를 유지해 일시정지하고 TTS는 중지한다. 안내가 열린 동안 재생 요청을 서비스에서도 차단하며, 지연 TTS 콜백/예약 다음 항목은 자동 재생하지 않는다. 나중에 하기/주차 해제 후에도 자동 재개하지 않는다. 화면 이동으로 오디오를 재시작/중복 재생하지 않는다.
- Media3 서비스의 PlaybackHistoryCollector가 5초 간격 및 상태/위치 변경, 차량 신호 처리 직전에 수집한다. 세션 경계에서 기준점을 다시 잡아 운행을 가로질러 청취 구간이 합쳐지지 않게 한다. 화면 이동과 무관하며, seek 전 위치를 닫고 새 기준점을 잡는다. 일시정지·버퍼링·건너뛰기는 청취로 세지 않고 겹친 재청취는 합친다.
- TTS는 시작 사실과 onDone 정상 완료만 기록한다. 시작/완료 사이 운행이 바뀌면 해당 운행 전체 청취로 인정하지 않는다. 정밀 구간/추정 재생시간을 실제 청취로 쓰지 않는다. 같은 ID라도 대본이 변경되면 별도 기록을 유지한다.
- 전체 대본 사용 가능 여부(canUseFullScriptForQuiz)는 대본 존재 + 전체 구간 청취 또는 TTS 정상 완료를 요구한다. 음원은 플레이어 이벤트 경계 오차만 개별 빈 구간 100ms 이하·총 누락 250ms 이하이면서 길이의 1% 이하로 허용한다. 큰 seek 누락·30% 청취·마지막 도달만으로 완료 판정하지 않는다. 부분 청취도 저장하지만 대본에 타임코드가 없어 들은 문장을 특정할 수 없으므로 전체 대본 퀴즈 대상으로 자동 처리하지 않는다. 실제 출제/청취량 정책은 후속 결정.
- 강제 종료 시 마지막 약 5초 및 비동기 저장 중 데이터가 유실될 수 있다. 손상·미지원 JSON 버전은 오류로 보고하고 원본을 덮어쓰지 않는다. 앱 삭제/데이터 초기화 시 기록도 삭제된다. 저장·복원은 오디 재생 큐/이어듣기 복원 기능과 별개다.

## LLM 퀴즈 (quiz)
- 화면: 종료 안내 → 문제 수/예상 시간/실제 대본 범위 → 객관식 3보기 → 정답 확인/해설/원문 인용 → 결과. 예상 풀이 시간은 문제당 30초, 권장은 운행 15분 미만 3/15분 이상 7/30분 이상 10문제.
- 현재 운행 ID의 전체 청취 확인 대본만 사용한다. 타임코드가 없어 부분 청취 구간→문장 매핑이나 해당 오디오 구간 점프는 제공하지 않는다. 제목만으로 문제를 생성하지 않는다.
- QuizCoordinator가 중복 요청/운행 변경/주차 해제를 검사한다. 주행/신호 불명 시 화면 숨김과 생성 취소·이전 응답 무시, 답안 변경 차단. 기존 TripPlaybackGuard로 안내/퀴즈 동안 오디오 일시정지 유지, 자동 재개 없음.
- Room에 문제·출처 대본·선택 답·정답 확인 여부·현재 인덱스를 운행/문제 수별로 저장한다. 같은 퀴즈는 재생성하지 않고 복원한다. MY POT의 최근 운행 퀴즈에서 이전에 사용한 문제 수를 선택하면 이어풀기/결과 확인 가능.
- 공급자 미지정으로 OpenAI를 기본 구성했다. 앱 QuizApi → PC 로컬 Node 중계 서버 → OpenAI Responses API/Structured Outputs. 기본 모델 gpt-4.1-mini, 서버 OPENAI_MODEL로 변경. 실제 키/호출 검증은 별도다.
- 키는 quiz-server/.env OPENAI_API_KEY에만 설정한다. 앱 BuildConfig에는 중계 주소(QUIZ_API_URL)만 둔다. .env는 기존 .gitignore로 제외한다. debug만 에뮬레이터/루프백 HTTP 허용, release는 HTTPS 서버 필요. 로컬 서버는 127.0.0.1 전용이며 공용 배포용 인증/운영은 제외한다.
- 서버/앱이 운행·문제 수·보기·출처·중복·대본 근거를 검증한다. 2026-11-14부터 정답 보기의 인용 내 문자 일치 조건은 제거하고, 근거 2~600자 및 공백/문장부호 정규화로 완화했다. 숫자 내 소수점/구분 기호는 보존한다. 의미적 출제 정확성은 실제 LLM 검증이 필요하다. 거부/불완전/근거 부족/통신 실패는 오류와 수동 재시도로 처리하며 예시 문제로 대체하지 않는다.
- 설정/실행/API 계약: quiz-server/README.md. 테스트 서버 응답과 실제 LLM 성공을 구분한다.

## 오디오 심사 정책
- 공식 Music/Audio 정책을 기준으로 팟캐스트 유형과 MBS 호환 MediaLibraryService로 개발한다. Manifest 오디오 카테고리·런처 메타데이터를 반영했다.
- 홈/탐색 화면 계약은 유지한다. 등록 음원만 시스템 브라우저에서 재생 가능하게 제공하고, 별도 TTS 시연을 표준 미디어 재생 준수로 간주하지 않는다.
- 제출 전 TTS/실제 음원과 시스템 플레이어 통합, 차량 키·포커스·Suspend·CarUxRestrictions 검증이 필요하다.
- 상세 기준/구현/미충족 구분은 docs/AUDIO_POLICY.md를 참조한다. 공모전 별도 공고는 추가 확인 필요.

## SDK 근거와 미확정 사항
2026-11-08 공식 문서 확인 기준:
- NaviHelper 3.0.5: getDestinationInfo() 요청 후 onDestinationInfo()로 수신.
- onDestinationChanged(), onDestinationArrived() 지원. 실제 이벤트 전달은 Navigation 앱 상태·구현에 따라 달라질 수 있다.
- 릴리즈 노트에 DestinationInfo.totalTime → remainTime 변경이 명시되어 남은 시간 필드 존재 확인.
- SDK 바이너리 선언 확인: DestinationInfo.name/address, latitude/longitude(Double), remainTime(Int). 에뮬레이터에서 목적지 이름·주소·좌표와 남은 시간 원본 수신 확인. 시간 단위·미설정 값·갱신 방식은 추가 검증하므로 현재 시간 기반 정렬은 보류한다.
- Maven: https://nexus-playground.pleos.ai/repository/maven-releases/
- 내비 의존성: ai.pleos.playground:NaviHelper:3.0.5 / 조회 권한: pleos.car.permission.NAVI_ROUTE
- 시연 음성: ai.pleos.playground:TextToSpeech:3.3.1 / pleos.car.permission.TTS_SERVICE / Mode.ON_DEVICE, Locale.KOREA.
- 표준 Android 한국어 TTS는 현재 에뮬레이터에서 사용 불가를 확인해 최종 구현에서 제외했다.
- 정차 판정은 별도 Vehicle SDK 대신 공개 AAOS android.car 라이브러리: CarPropertyManager의 GEAR_SELECTION/PERF_VEHICLE_SPEED, CarUxRestrictionsManager를 사용한다. CAR_POWERTRAIN 선언과 CAR_SPEED 런타임 승인이 필요하며 거절/미지원은 잠근다. 공식 근거: https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide 및 https://developer.android.com/reference/android/car/VehiclePropertyIds .
